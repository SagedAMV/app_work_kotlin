## جلسة ترتيب واجهة المجرة (2.10.0)

**السبب الجذري للمشكلة** (تحليل 5-لماذا): التوزيع الأساسي قوة-موجهة عامة تعامل الشبكة كتلة واحدة، فتتحول الرسوم الكثيفة إلى «كرة خيوط» متداخلة، والمكونات المنفصلة تختلط، والإزاحات اليدوية تتراكم بلا سبيل لتنظيفها.

**الحل** — ثلاثة ملفات:
- `util/NetworkLayout.kt`: دالة `arrange` الجديدة — تعقيم المدخلات، فصل المكونات (Union-Find مع ضغط المسار)، تخطيط شجري شعاعي حتمي للأشجار (جذر = الأعلى درجة، قطاعات زاوية موزونة بعدد الأوراق، حساب تكراري بلا استدعاء ذاتي مأمون مع السلاسل الطويلة)، استرخاء قوة-موجهة محلي بتكرارات متكيفة للكثيف (260 تكرارًا حتى 140 عقدة ثم تتناقص حتى حد أدنى 90)، تعبئة خلايا شبكة (صفوف/أعمدة محسوبة من نسبة أبعاد العالم، المكونات الأكبر تأخذ الخلايا الأولى)، وخطة طوارئ: `runCatching` حول المسار الذكي ثم `compute` ثم `gridFallback`، مع فحص `isComplete` (اكتمال + إحداثيات منتهية) قبل كل إعادة. الفيزياء الأصلية عُزلت إلى `relax` كما هي حرفيًا ليشاركها المساران — تحقق عددي خارجي أكد تطابق نتائج `compute` قبل العزل وبعده.
- `ui/screens/galaxy/GalaxyNetworkScreen.kt`: مؤقّت ضغط مطوّل (480 مللي ثانية) داخل حلقة الإيماءة يعمل فقط فوق مكان فارغ وفيه مواقع — يعمل كوروتينًا ابنًا يطلق اهتزازًا ويضع مرساة الزر، وتلغيه الحركة أو إصبع ثانٍ أو الرفع؛ زر «ترتيب» طافٍ ينبثق عند المرساة مثبتًا داخل حدود الشاشة؛ عند الضغط: `ViewModel.arrangeSites` يحسب على `Dispatchers.Default` ويبث الأهداف، الشاشة تلتقطها وتنزلق بالعقد (950ms) ثم تثبّت الإزاحات (`applyArrangement` تصفّي المعرفات الحية فقط) وتلائم العرض (FitAnim). مواضع الرسم أثناء الانيميشن مستوفاة بين القديم والجديد، والسحب اليدوي مقفل خلالها، ونقرة الفراغ تُغلق الزر.
- `app/src/test/.../NetworkLayoutTest.kt`: 11 حالة جديدة لـ`arrange` (فارغ/مفرد/حدود/حتمية/استقلال الترتيب والاتجاه/روابط معطوبة/تباعد المكونات/نجمة/رسم 300 عقدة < 3 ثوانٍ/كثافة كاملة).

**التحقق المنطقي المنفَّذ في هذه الجلسة** (بيئة بلا Android SDK): نُقلت الخوارزمية حرفيًا إلى سكريبت تحقق مستقل شغّل 21 فحصًا — كلها ناجحة: تطابق `compute` المعزول مع الأصلي على رسمين، وكل خصائص `arrange` المذكورة أعلاه، وقياس أداء 61ms لرسم 300 عقدة/350 رابطًا.
